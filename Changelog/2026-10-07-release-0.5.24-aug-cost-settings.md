# RynthAi 0.5.24-legacy-ui — Aug costs use UB's InfiniteLeaftide math, with per-server settings

**Date:** 2026-10-07
**Previous release:** 0.5.23-legacy-ui
**Branch:** `main`
**Pairs with:** RynthCore engine 2026.10.5.18, which draws the Cost settings editor. With an older
engine the new math still applies; only the editor is missing.

## Why

UB-IT's aug luminance math is the correct one for InfiniteLeaftide. Ours differed from it in three
ways:
- Each price step (×4, ×8, ...) started one level later than UB-IT's.
- Specialization and Summon had different thresholds.
- Every aug had a target cap.

Other servers may price augs differently, so the multipliers and per-aug rules can now be set
per server.

## The model (new `IltHub/IltAugCosts.cs`)

- Level *i* (counting from 1) costs `(Base + (i - 1) × Base × Growth% / 100) × multiplier`. The
  multiplier is M0 below S1, M1 from S1, M2 from S2, M3 from S3 and M4 from S4. A tier starts *at*
  its S level, as in UB's `GetCumulativeCost`.
- **Defaults (UB `Augs.cs`):**
  - multipliers 1 / 4 / 8 / 16 / 24;
  - the same base, growth and coins per level as before;
  - Specialization and Summon thresholds are now 1750 / 2500 / 3000 / 3750 (they were
    1750 / 2000 / 2250 / 2750 and 1250 / 2000 / 3000 / 3500);
  - no target cap. The planner still stops at 100,000, and a cap can be set per aug.
- Costs are summed per tier in closed form (each tier is an arithmetic series) instead of level by
  level, so a large target can't stall the plugin. A test checks it against a copy of UB's loop.

## Per-server settings

- Saved in one shared file, `<RynthAi folder>\ilt-aug-costs.json`, keyed by world name (case
  ignored). Every character on a world uses the same rules. A world with no entry uses the
  defaults.
- New `prog` commands from the Skills panel:
  - `augmult <tier 0-4> <multiplier>`: decimals allowed, 0 to 1000.
  - `augcfg <aug> <base|pct|coins|s1|s2|s3|s4|cap> <value>`: base accepts k / m / b / t.
  - `augcfgreset`: drops this world's rules, so it goes back to the defaults.
- Saved values are kept sane: each aug has exactly one row, numbers can't go negative, and S1 ≤ S2
  ≤ S3 ≤ S4 (lowering a threshold below the one before it snaps it up to that one).
- The Progression snapshot adds `aug.cfg` (world, custom, mults, rows), which the editor reads.

## Tests (`Tools/RynthCore.RynthAiHostTests`)

- "aug costs: UB's ILT model (tier starts at its S level) in closed form" checks:
  - S1 − 1 is the last ×1 level and S1 is the first ×4 level;
  - the Specialization / Summon thresholds and no default cap;
  - the closed form equals UB's loop on several ranges and with custom multipliers.
- "aug costs: per-server multipliers and rules, saved and reset" checks:
  - an edit makes the world custom and re-prices the plan;
  - the base suffix and S ordering;
  - other worlds are untouched;
  - the rules reload from the file, and a reset is saved.
- The tests write the settings file to their scratch folder (`IltAugCosts.FilePath`).
- Full run: 435 passed, 5 known failures. One unrelated failure remains: the map-bake check, which
  depends on the local DAT files.
