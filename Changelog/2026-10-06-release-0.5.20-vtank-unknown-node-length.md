# RynthAi 0.5.20-legacy-ui — unknown loot condition types no longer swallow neighbouring rules

**Date:** 2026-10-06
**Branch:** `fix/vtank-unknown-node-length` (from `fix/corpse-killer-decay-line` f2f970e)
**Previous release:** 0.5.19-legacy-ui

## Problem

Silentkelpie never looted some items its loot profile (`T10locky.utl`) asks for, Bewitching
Baubles and cloaks among them.

- Three rules in the profile used condition types RynthAi doesn't know (2009, 2011, 2016). They
  aren't standard VirindiTank types, so some other editor wrote them.
- The parser knows how many data lines each known type has. For an unknown type it read lines
  until something looked like the start of a rule.
- "essance 2" began with an unknown 2011 condition. The guess swallowed the rest of that rule,
  and its five remaining conditions then read their data from the following lines, swallowing
  the "Cloak" and "(T) bewitching" rules. Neither was ever loaded.
- "Encapsulated Spirit" (unknown 2016) was the last rule. It swallowed the SalvageCombine block,
  so the profile's salvage-combine settings were ignored.
- A rule with an unknown condition never matches, so all of this was silent: nothing in chat
  or the log said why the items stayed on corpses.
- The header also declared 134 rules when the file held 136 (two are disabled rules with blank
  names). Swallowing two rules had happened to hide that.

## Fix

- `VTankLootParser` reads an unknown condition's data using its length code, which is the byte
  length of the data block with 2 bytes per line break. Lines are taken only when they add up
  to the code exactly, counted as characters (ANSI files) or as UTF-8 bytes. Otherwise it falls
  back to the old guess. A code of 0 also falls back, because `VTankLootWriter` writes 0 for
  conditions built in code.
- The parser keeps reading rules after the header's count while the next lines still look like
  a rule, so an undercounted header no longer drops the last rules. The declared count is
  available as `VTankLootProfile.DeclaredRuleCount`, and a re-save writes the true count.
- When RynthAi loads a loot profile, it reports in chat and in the Looting log:
  - a header count that disagrees with the rules found;
  - each rule that uses an unsupported condition type, with the type numbers.

## Profile repair (deployed file, not in the repo)

`C:\Games\RynthSuite\RynthAi\LootProfiles\T10locky.utl` was edited, with the user's agreement
on each rule. A backup is at `T10locky.utl.bak-2026-10-06`.

- "Encapsulated Spirit": the 2016 condition is now a name match on "Encapsulated Spirit".
- "Cloak": the 2009 condition is now "name contains Cloak" plus "class is Clothing". The three
  rating checks (properties 370, 375, 377 at least 9) are unchanged.
- "essance 2": deleted. The "essance" rule already makes the same five rating checks on class
  Misc, which is the class pet essences have.
- The header count is now 135, matching the file.
