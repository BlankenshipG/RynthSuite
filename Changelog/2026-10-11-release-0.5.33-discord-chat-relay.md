# RynthAi 0.5.33-legacy-ui - Discord chat relay

**Date:** 2026-10-11
**Previous release:** 0.5.32-legacy-ui
**Branch:** `feat/discord-chat-relay`

## What's new

RynthAi can copy the chat channels you choose into a Discord channel, by webhook or by bot.

- **Routes:** each route is one Discord channel and the chat it receives. Add as many as you like,
  e.g. Allegiance into `#allegiance` and Tells into a private channel.
- **Destination per route:**
  - **Webhook URL** (simplest): Discord > Server Settings > Integrations > Webhooks > New Webhook,
    pick the channel, Copy Webhook URL, paste it in RynthAi and press Save. "Post as" sets the name
    shown on the messages; blank uses the character's name.
  - **Bot token + channel ID:** for a bot you already run. The bot needs View Channel and Send
    Messages in that channel. Channel ID: Developer Mode on, right-click the channel, Copy Channel ID.
- **What is relayed:** tick any of Local, Tell, Fellowship, Allegiance, Patron, Vassals, Covassals,
  Monarch, General, Trade, LFG, Roleplay, Society and Olthoi. **Other** adds lines that aren't player
  speech (system and server broadcasts); it is busy, so pair it with **Keywords** (comma-separated,
  any case; only lines containing one of them are sent).
- **Format:** `` `09:05:07` **[Allegiance] Bob:** inc at the portal ``. The timestamp and a
  `[Character]` prefix can be switched on or off.
- **Several clients:** "Only these characters" (Settings tab) limits relaying to the characters
  named, so a line seen by three of your characters in one allegiance is posted once.

### Window and commands

- `/ra discord window` opens the **Discord Relay** window: Routes (one tab each, with Send test and
  Resume), Log (messages sent, rate limits, errors) and Settings.
- `/ra discord on|off`, `/ra discord test [route]`, `/ra discord resume [route]`,
  `/ra discord` (status of every route).

## Safety

- **No pings:** every message sets `allowed_mentions` to nothing, and `@everyone` / `@here` are
  defused in the text. Discord Markdown in chat (bold, code, spoilers, links, `<@id>` tags,
  headings) is escaped, so a chat line can't format or ping. Link previews are suppressed.
- **Secrets encrypted:** webhook URLs and bot tokens are stored only as Windows DPAPI blobs
  (CurrentUser) in `RynthAi\discord.json`, decrypted at the moment of sending, and never shown,
  logged or echoed. Copied to another Windows user or PC, they must be pasted again.
- **Discord hosts only:** a webhook URL is accepted only for `discord.com` / `discordapp.com`
  (`ptb.` / `canary.`) `/api/webhooks/<id>/<token>` over https, so a typo can't send chat elsewhere.
  Redirects are not followed.
- **Rate limits:** lines arriving within the batch window (1.5 s) go out as one message of at most
  2000 characters; posts to a route are at least 2 s apart (about 30 a minute, Discord's per-channel
  limit). A 429 waits exactly as long as Discord asks; an empty rate-limit bucket is honoured too.
- **Bad credentials stop:** HTTP 400 / 401 / 403 / 404 pause the route (shown in red with the
  reason) instead of retrying, since Discord temporarily bans clients that keep sending invalid
  requests. Saving a new URL / token, Send test or Resume clears the pause. Network errors and 5xx
  retry with backoff (2 s doubling to 60 s), at most 5 times per message.
- **Bounded:** at most 200 lines queued per route (oldest dropped and counted), 2000 raw lines
  waiting overall. All posting runs on a background task; chat hooks only enqueue.
- Lines the ILT Hub or Meta Manager eat (their own command replies), the translator's
  `[Translate]` echoes, the relay's own `[Discord]` lines and spell words are never relayed.

## How it works

- `Discord/DiscordRelay.cs`: the chat hook enqueues; the plugin pump thread parses (the
  translator's channel parser), routes, batches and starts at most one post per route. Results come
  back through a queue. The window reads status and the log through snapshots.
- `Discord/DiscordClient.cs`: `HttpClient` with a 15 s timeout; JSON written with
  `Utf8JsonWriter` and read with `JsonDocument` (NativeAOT-safe). Webhook: `POST <url>`. Bot:
  `POST https://discord.com/api/v10/channels/<id>/messages` with `Authorization: Bot <token>`.
- `Discord/DiscordFormat.cs`: escaping, line format, packing, credential-shape checks, filters.
- `Discord/DiscordSecrets.cs`: DPAPI with its own entropy (`RynthCore.RynthAi.DiscordRelay.v1`).
- `Discord/DiscordRelaySettings.cs`: settings and `discord.json` store (written only when changed,
  via a temp file). Shared by every character, like `translate.json`.
- `Discord/DiscordRelayUi.cs`: the window.
- Wired in `RynthAiPlugin.LocalFeatures.cs` (create at login, tick, chat, render, dispose) and
  `RynthAiPlugin.cs` (shutdown, `/ra discord`). `RynthAiJsonContext` gains `DiscordRelaySettings`.

## Not included

## Tests

- New `Tools/RynthCore.RynthAiHostTests/Tests/DiscordRelayTests.cs`: 11 tests, 99 checks, all
  passing. They cover webhook URL hosts, bot token / channel ID shapes, Markdown and mention
  escaping, line format and truncation, packing under 2000 characters, chat classification, keyword
  and character filters, webhook names, 429 / permanent error handling, the request body, and a
  settings round-trip that confirms the webhook URL is not stored in plain text.
- The fake webhook URL and bot token used by these tests are built at runtime, so the source has
  no credential-shaped strings for GitHub push protection (secret scanning) to block.
- Full RynthAi host tests: 481 tests, 475 passed, 5 known failures, 1 failure (the map bake, which
  needs the real dat files on this machine - same as 0.5.32).
- `dotnet publish -c Release` (NativeAOT x86): no warnings.
- Not yet tried against a real Discord server in game.
