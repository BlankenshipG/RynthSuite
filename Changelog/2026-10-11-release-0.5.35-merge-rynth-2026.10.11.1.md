# RynthAi 0.5.35-legacy-ui: local build merged with rynth release 2026.10.11.1

**Date:** 2026-10-11
**Previous release:** 0.5.34-legacy-ui
**Branch:** `build-comp-10-11` (local only, not pushed)

## What this is

`main` plus rynth's `aelrynth/main` (release 2026.10.11.1), so the local test build carries both
our unreleased work and everything rynth shipped since the last sync.

## How the conflicts were settled

- **Rynth's side** wherever he reworked something we had also fixed:
  - pet essence refill-loop guard (`PetManager`: `ServerSaidFull` / `RefillLooping`);
  - typed-object filing (`WorldObjectCache.FileTypedObject` / `WhoHas`);
  - spell category and power (`SpellDatabase`);

  - dungeon hazards, radar walls, meta UI and install paths in `MetaManager`.
- **Our side** for:
  - the T11 loot catalog, keys, item info and `/ra t11` (ours is newer);
  - `LootItemRules`;
  - the T11 loot tests;
  - `RynthLog` categories in loot logging.
- **Both:**
  - `LootRuleText` (rynth's text plus our T11 property keys and the Gear Grade value table);
  - the `MonsterEditor` JSON context (adds our UB mob seed type);
  - chat hooks (`OnChatLocalFeatures` and rynth's hotspot check);
  - the host test list.
- A pyreal-refill essence that still reports "not enough charges" is parked again (ours), on top
  of rynth's refill guard.

## Item info: ours, with rynth's extras

Both sides had a `/ra iteminfo`. The local build keeps ours (the Mag-Tools port with the settings
window, field and rating toggles, click trigger, pet or line layout and the T11 fields). It also
takes from rynth's:

- `/ra iteminfo <item name>`: describes an inventory item by name (exact match first, else the
  first name that contains it).
- Items RynthAi selects itself (looter, meta `selectitem`; `ItemInfo/SelfSelect`) are not
  described, and still get the old loot verdict line.
- The item info line ends with the looter's verdict (`| Loot: [Keep] rule`). The verdict is a
  preview; nothing is recorded.
- The default prefix is now `[RynthAi Item] `, so RynthChat files item info under its Items tab.
  Profiles that saved their own prefix keep it.
- Rynth's "Item Info On Select" checkbox (Advanced Settings), the meta setting `ItemInfoOnSelect`
  and the engine's settings DTO now drive our `ItemInfoSettings.OnSelect`. An **Options** button
  next to the checkbox opens the Item Info window.

Removed rynth's duplicates: `RynthAiPlugin.ItemInfo.cs`, `ItemInfo/ItemInfoText.cs`,
`Tests/ItemInfoTests.cs`, the plain `ItemInfoOnSelect` settings field, his second
`case "iteminfo"`, and his second `TickItemInfo()` call.

## Shared install paths

Our `Shared/RynthInstallPaths.cs` is gone. Everything links rynth's read-only
`Plugins/Shared/RynthInstallPaths.cs`, which is byte-identical to RynthCore's
`src/Shared/RynthInstallPaths.cs`. The RynthAi plugin and the Monster Editor were relinked.
