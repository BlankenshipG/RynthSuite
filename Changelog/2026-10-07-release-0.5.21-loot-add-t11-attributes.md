# RynthAi 0.5.21-legacy-ui — "Add to loot profile" can include an item's T11 attributes

**Date:** 2026-10-07
**Branch:** `feat/loot-add-t11-attributes` (from `fix/vtank-unknown-node-length` 916acf4)
**Previous release:** 0.5.20-legacy-ui
**Engine side:** RynthCore 2026.10.5.15, branch `feat/loot-add-t11-checkbox` (the popup's checkbox)

## What's new

"Add to loot profile" builds a loot rule from a clicked item. It now has an
**Include T11 attributes** option:

- a checkbox in the popup (Inventory panel right-click, or "Add selected item" in the Loot Editor);
- `t11` in the chat command: `/ra loot add [keep|keep N|salvage|sell|read] [name|like] [t11] [preview]`.

When it's on, the rule also requires the item's T11 attributes. Each one must be **at least as
good as the clicked item's**, using RynthAi's virtual T11 keys:

| Condition | From |
|-----------|------|
| T11: Is T11 = 1 | always, for T11 gear |
| T11: Tier (est.) >= N | the wield gates |
| T11: Weapon Grade >= N | the "Weapon Grade" line (weapons) |
| T11: Damage % of Max >= N | the grade line |
| T11 Mod: <name> >= N | each catalogued modifier with a value |
| T11: Has Slot Special = 1 | a value-less slot special (Fortify Vitals, Battle Mending...) |
| T11: Cast on Strike Count >= N | the Cast on Strike lines |

The option works with every match mode (name + class, name only, items like this).

Left out on purpose:
- **Can Wield** depends on the character, not the item.
- **Zone Locked** depends on where the item was assessed.
- **Wield gates** follow from the tier.
- **Modifier count, rating total and roll %** follow from the per-modifier values. TotalRatings is
  already in "items like this" and reads T11 ratings.

## Notes the popup shows

- A non-T11 item: "Not a T11 item, so there are no T11 attributes to add." The engine popup also
  shows "(not a T11 item)" next to the checkbox.
- A T11 item that hasn't been identified: only "Is T11" is added, and a note says to assess it.
  RynthAi asks the server for the ID, so the next preview has the full list.
- A modifier the catalog doesn't know (for example "Modifier 60" from a newer server) has no loot
  key; it is named in a note and left out.
- "Items like this" no longer warns "matches every <class>" when T11 conditions narrow it.

## Wire (LootEditWire)

- `LootEditItemRequest.IncludeT11`: an older engine never sends it, so it reads false.
- `LootEditItemDraft.IncludeT11` and `IsT11`: an older engine ignores them.
- An older RynthAi ignores the engine's checkbox, and its draft says `IsT11 = false`.

## Code

- `LootItemRuleOptions.IncludeT11`, `LootItemFacts.T11` (the item's `T11ItemInfo`).
- `LootItemRules.AddT11Conditions` builds the conditions.
- `LootItemHooks.Facts` takes a third flag (include T11). `BuildLootItemFacts` always fills the
  T11 reading (a cached parse), and with the option on asks for an ID when a T11 item has no
  text yet.
