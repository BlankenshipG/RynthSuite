# RynthAi 0.5.23-legacy-ui — Progression tab: UB-style manual attribute raises and aug planner

**Date:** 2026-10-07
**Previous release:** 0.5.22-legacy-ui
**Branch:** `main`
**Pairs with:** RynthCore engine 2026.10.5.17 (`QOL-items`), which draws the new layout. An older
engine still works with this RynthAi; it just shows the old layout.

## Why

There was no practical way to raise attributes by hand from the Progression tab. The live builds
(engine 2026.10.5.15, RynthAi 0.5.21) have no attribute raiser at all. On the newer builds the +1 / +10
buttons existed but didn't show what they cost, and the costs weren't read until you pressed
Refresh. The Augmentations section also lacked most of what UB's ILT Tools Augs tab offers.

This release follows UB's Leaftide `XPCalculator` / XP tab and its `Augs` tab.

## Attributes (`IltHub/IltAttributeRaiser.cs`)

- **Costs on the buttons.** Each row reports the server's next-level cost from `/xp all`, plus a
  projected cost for ten levels. The projection uses UB's `EstimateMultiLevelCost`, where each
  level costs 7.7% more than the last (`ProjectCost`, `ProjectedLevelGrowth = 0.077`). The server
  still charges the real cost.
- **Affordability check before sending.** A manual +1 / +10 whose known (or projected) cost is
  more than your unassigned XP is refused with "Not enough unassigned XP for X +N: need ..., have
  ...", the same check as UB's `UseXPOnAttribute`. If a cost hasn't been read yet, the raise is
  sent anyway and the server decides. Manual raises ignore the raiser's reserve.
- **Costs read when the tab opens.** The first time the Progression tab is shown after login,
  `/xp all` runs once (`EnsureCosts`), as UB's XP tab does on load.
- New snapshot fields:
  - top level: `updated` (local time the costs were read) and `xpHeader` (level, total XP,
    unassigned XP);
  - per row: `known`, `afford1`, `afford10`, `cost10`, `costFull`, `cost10Full`.

## Augmentations (`IltHub/IltProgression.cs`)

- **Current pulled automatically.** If no levels are loaded (by the login probe or by hand),
  opening the tab sends `/aug` once per login (`EnsureAugs`).
- **Reset targets:** the new `prog augreset` command sets every target back to the current level
  (UB's Reset Target).
- **Inc and totals:** each row now reports `inc` (target minus current). The snapshot adds totals
  (`totCur`, `totTgt`, `totInc`, `totLum`, `totCoins`), an e-coin line (needed, banked, short) and
  the luminance needed to buy the coins you're short (`lumToBuy`).
- **Copy texts:**
  - `copyDiscord` is UB's code-block table (Type, Current, Target, Inc, Lum Cost, Coins, plus a
    TOTALS row).
  - `copyIngame` is one chat line of current levels with UB's short names (Crit, Item, Life, War,
    Void, Dur, Spec, Sum, Mel, Mis).
  - Both are plain ASCII, because the engine reads the snapshot as ANSI, so UB's emoji and
    box-drawing rules are replaced with dashes.
- The plan math moved into one `BuildAugPlan()`, so the table, totals and copy texts can't
  disagree.
- The older `total` / `short` / `banked` fields are still sent for older engines.

## Not changed: our aug luminance model differs from UB-IT

Comparing with UB-IT's `Augs.cs` turned up two differences. They are left as they were until we
know which one matches the server:

1. **Price step lands one level later.** In UB, level *i* (counting from 1) costs ×4 once
   *i* ≥ S1, ×8 once *i* ≥ S2, and so on. Ours counts from 0 (`n >= S1`), so the level exactly at
   each threshold is priced one tier lower here than in UB.
2. **Different thresholds for two augs:**

   | Aug | Ours (S1, S2, S3, S4) | UB-IT (S1, S2, S3, S4) |
   |---|---|---|
   | Specialization | 1750, 2000, 2250, 2750 | 1750, 2500, 3000, 3750 |
   | Summon | 1250, 2000, 3000, 3500 | 1750, 2500, 3000, 3750 |

## Tests (`Tools/RynthCore.RynthAiHostTests`)

- New: "attr raiser: by-hand +1 / +10 priced like UB, refused when unaffordable, costs read on tab
  open". It checks the 7.7% projection (1,000 for one level, 14,281 for ten), the one-time cost
  read, the snapshot fields, and that an unaffordable +10 is refused while an affordable +1 is sent.
- New: "aug planner: /aug pulled on tab open, totals, reset targets, copy texts".
- All the existing attribute raiser and server feature tests pass.
- Full run: 432 passed, 5 known failures. One unrelated failure remains, "map bake: 0x6346 from
  the real dats matches the plan already on disk", which depends on the local DAT files.
