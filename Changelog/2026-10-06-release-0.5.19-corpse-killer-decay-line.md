# RynthAi 0.5.19-legacy-ui — own kills no longer skipped when the corpse shows its decay timer

**Date:** 2026-10-06
**Branch:** `fix/corpse-killer-decay-line` (from `main` c1ccf5e)
**Previous release:** 0.5.18-legacy-ui

## Problem

Silentkelpie left Necrolytic Extract (and everything else) on some of its own kills. The loot
profile (`T10locky.utl`) has a Keep rule for it, but those corpses were never opened.

- Loot From is "Fellowship Kills" and Silentkelpie is not in a fellowship, so a corpse is looted
  only when its killer is the current character.
- The killer comes from the corpse LongDesc line "Killed by X.". The parser took everything after
  "Killed by ", so once the server added "Corpse will decay in 56s" under it (corpses that waited
  for a fight to end), the killer read as `Silentkelpie.\nCorpse will decay in 56s`.
- That never equals `Silentkelpie`, so the corpse was skipped as someone else's kill:
  `ownership skip … killer='Silentkelpie.\nCorpse will decay in 56s' me='Silentkelpie' reason='Not in a fellowship and the corpse killer does not match the current character.'`
- 22 own kills were skipped this way in one session (pid 29000, 15:15–15:23), and 4 in the
  2026-10-06 00:14 session. Corpses reached before the decay line appeared were looted normally.

## Fix

- `RynthAiPlugin.ExtractCorpseKillerName` reads only the "Killed by" line: it stops at the first
  line break, then trims spaces and the trailing period.
- The radar's killer column (`RynthRadarUi.ExtractKiller`) now calls the same method instead of
  keeping its own copy (it had the same flaw).
- Recover My Corpse uses the same method, so a decaying death corpse is still recognised.

## Tests

- New `Tools/RynthCore.RynthAiHostTests/Tests/CorpseKillerTests.cs` (5 tests): plain line,
  decay line after the killer, CRLF and multi-word names, no killer line, radar parity.
- Host tests: 423 passed, 5 known failures, 1 unrelated failure (map bake reads the real dats).
