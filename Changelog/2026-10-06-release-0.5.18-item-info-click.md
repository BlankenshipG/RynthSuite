# RynthAi 0.5.18-legacy-ui: item info replaces the loot rule line on select / click

Date: 2026-10-06
Branch: `feat/t11-loot-support` (uncommitted, on top of 0.5.17)

## Problem

With item info set to print on a left or right mouse click, selecting an item printed the
loot inspect verdict (`<item>: [Keep] New Rule`) instead of the configured item info output.

Cause, in `RynthAiPlugin.OnSelectedTargetChange`:
- Loot inspect is on by default (`_lootInspectMode = true`) and printed its verdict for every
  item selected, whatever the item info settings were.
- Item info on select was queued from inside that loot inspect block. It only ran while loot
  inspect was on, and it ignored the "Print on select" setting (`OnSelect`).
- No item info trigger wrote anything to the logs, so the logs couldn't show what happened.

## Fixes

- **Item info replaces the loot verdict.** When item info is enabled for the selected item's
  class (on select or on a mouse click), the loot rule line is no longer printed. With item info
  off, the loot verdict prints as before. `/ra lootcheck` still prints it on demand, and
  `/ra lootcheck off` turns the automatic line off.
- **"Print on select" is honoured.** The select trigger only queues item info when `OnSelect`
  is on, and it no longer depends on loot inspect being on. The click trigger is unchanged.
- **Logging.** Each trigger decision writes one `[ItemInfo]` line to the engine log
  (`C:\Games\RynthCore\Logs\RynthCore.<pid>.log`) and the daily RynthAi diagnostics file:
  - on-select queue;
  - click queue, or why a click was skipped (nothing selected, not cached, class filter);
  - deduped by the other trigger;
  - waiting for ID data;
  - printed (line count, identified flag, first line), or why nothing printed.

## Note on settings

Silentkelpie's item info prefix is an empty string, so its lines print without the
`[RynthAi] ` prefix. Set it in the Item Info window if the prefix is wanted.
